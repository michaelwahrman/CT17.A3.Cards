What it is

Browser-based WebGL / three.js card games. A1 = Klondike, A2 = click-to-move, A3 = FreeCell, a game switch, and video recording. Open index.html directly (double-click works; no server needed, and nothing is loaded from the internet).

Changes in A3

Game switch

  • Klondike | FreeCell segmented button at the top (key G toggles). The cards are swept together into the new game's deck spot, shuffled and dealt into the new layout. The choice is remembered (localStorage CT17.game).
  • Controls that only apply to one game are shown only for that game (.only-klondike / .only-freecell in index.html): Klondike: Next Card, Draw 1/3, Deck uses. FreeCell: Game #, Auto-play.
  • Title, splash, help and status bar follow the game.

FreeCell (js/games/freecell.js)

  • Standard rules. There are 4 free cells (top left), 4 foundations (top right) and 8 columns, all 52 cards dealt face up. Columns build down in alternating colours; any card may go to an empty column.
  • Microsoft deals: Game #1–#32000 use the Windows FreeCell LCG and deal, so the layouts are identical. This was checked: #1 starts JD 2D 9H JC 5D 7H 7C 5H / KD KC 9S 5S AD QC KH 3H and #617 starts 7D AD 5C 3S 5S 8C 2D AH. Deal New Game picks a random number; type a number in Game # and press Enter for that deal. The status bar shows Game #.
  • Supermove: a run may move at once if it could be done one card at a time: (empty free cells + 1) × 2^(empty columns). The target being an empty column doesn't count as one of those empty columns. The status bar shows "Free cells n · move up to k".
  • Click (A2 rule): the card moves to a foundation, else onto a column card, else (single card) to a free cell, else to an empty column. Clicking inside a valid run moves the run. Free-cell cards click to foundation or column. If no move exists, a "nope" sound plays. Drag still works.
  • Auto-play (toggle, default on): after each move, cards that are no longer needed go up to the foundations. "Safe" means rank ≤ 2, or both opposite-colour foundations already have rank − 1. These auto-moves share the undo step of the move that caused them (move(..., {noHistory:true})), so one Undo takes back the move and its auto-plays.
  • Auto-finish starts when every column runs downhill to its top card. Then come the win fanfare, the cascade and "You Won!" (with the Game #).
  • Dealing: the deck waits face down in the middle of the table (hidden pile deck). The 52 cards fly out row by row and flip face up in flight.

Video recording: the same mechanism as CT54.A6 → CT55.A7 → CT40.A12

  • ● Record button (key V). Press again (■ Stop) and the MP4 downloads as CT17.A3.Cards_YYYYMMDD_HHMMSS.mp4. No ffmpeg, no server, no batch file.
  • js/rec.js is CT40.A12.Solari.rec.js unchanged except that its global is renamed CT17Rec. It encodes with WebCodecs and muxes with mp4-muxer 5.2.1 (js/lib/, MIT). It tries constant-quality software H.264 first, then H.264 profiles, then VP9; each must encode a test frame. It uses AAC sound, else Opus. URL options: ?q=18 (lower = sharper), ?mbps=, ?encoder=hw.
  • Resolution: the table canvas at its real device-pixel size (rounded to even numbers, up to 3840×2160). The movie shows the 3D table, not the HTML top bar or status bar. A caption in the lower left shows game, Game #, moves and time, and the "You Won!" banner is drawn into the movie when it shows.
  • Speed: new js/clock.js. Every tween, deal timer, auto-play/auto-finish step and the game timer runs on CT17.clock (no more performance.now()/setTimeout for game timing). While recording, the clock is the movie's clock: each drawn frame advances it exactly 1/60 s and becomes movie frame i at i/60 s. It never runs ahead of real time. If the encoder falls behind, the screen slows and the movie still plays at normal speed. On Stop the clock continues smoothly in wall time.
  • Sound: js/audio.js now writes every sound against an env {ctx, master, noiseBuf}. Live, sounds go to the speakers. While recording, each sound is also logged with its movie time. At Stop the log is rendered again with the same synth in an OfflineAudioContext (48 kHz stereo, exactly as long as the picture) and added to the movie. Muted sound gives a silent movie.
  • The status bar shows ● REC m:ss · W×H 60 fps · codec · sound AAC/Opus while recording, then where the file was saved.
  • The encoder for the current window size is probed in the background 1.5 s after load, so Record starts at once.

  • Both games deal with 52 cards. Real mouse clicks on Klondike and FreeCell cards made their moves. The game switch works. Microsoft deal #1 matches. Undo and the supermove limit work, auto-finish wins, and there were no page errors.
  • Recording on a machine drawing only ~5 fps (software GL) took 42 s of real time to draw a deal. The movie came out at 960×484, a constant 60 fps, 4.18 s long, with the deal at its normal 3.95 s speed and an Opus sound track of matching length, max −8 dB. Throughput on a real GPU wasn't measured there. The user tests that on their own machine.
  • tests/test_ct17_a3.js (Playwright) is the self-test: node tests/test_ct17_a3.js [outdir]. Its live-vs-movie deal timing and frame-count assertions were still being tightened when testing was handed to the user, so expect those two to need adjusting on a slow machine.

Features from A1/A2 (unchanged)

  • Klondike: Deal New Game (D) sweeps, shuffles and deals 28 cards in the traditional order. Next Card / Next 3 Cards / Turn Deck Over / Deck Used Up (Space/N or click the stock). Draw 1/3 can change at any time. Deck uses 1–5 or Unlimited, default 3.
  • Undo (U / Ctrl+Z / Backspace, 500 deep). Dragging; single click = best move (A2). Face-down cards turn over automatically. Auto-finish, the win cascade, moves and timer. Settings persist. All sounds are synthesized (snap, slide, flip, riffle, nope, chime, win).
  • Card art from the prototypes (tools/prep_art.py → art/, data-URLs in art/art.js); the rest is drawn in js/cardart.js. A3 adds two slot drawings: freecell (open diamond, "free") and tableau-any (plain outline, any card).

Architecture notes (for adding games)

  • Game module shape: key, name, columns (layout width), deckPile (where the deck sits before a deal; may be a hidden:true pile), hasStock, pileSpecs ({id, kind, col, row, fan:'stack'|'waste'|'down', hidden?}), cards, state.piles, newGame(arg), dealOrder, canPickUp, canDrop, move(from,i,to,opts) → {flipped}, draw(), autoTarget(), undo(), isWon(), canAutoFinish(), nextFinishMove(), recyclesLeft(). Optional: safeAutoMove() (auto-play).
  • Both games use the same 52 card ids (suit 0♠ 1♥ 2♦ 3♣, id = suit×13 + rank − 1), so the view keeps one set of card meshes and view.setGame(game, true) only rebuilds the slots. The controller then gathers and deals the cards with animation.
  • Slot kinds: stock, stock-empty, waste, foundation, tableau (K), freecell, tableau-any. Hidden piles have no slot.
  • Anything timed must use CT17.clock.now() / CT17.clock.after(), or it will be wrong in movies.
